# Cooked animation packages and named frame differences

CyUEDiff Core reads explicit **UE 5.3 Windows editor-stripped AnimSequence native windows** without linking or launching Unreal. It extracts per-track compressed bone data from a verified IoStore package, selects the actual registered supported codec and optionally binds the exact referenced Skeleton. The reusable result is immutable. This is separate from source AnimDataModel inspection and from gameplay animation, retargeting, additive-base application or skin evaluation.

## Context and dependency proof

`read_zen_animation` requires `CookedAnimationProfile::unreal_5_3_windows`, a matching Zen profile/global script table and a successfully decoded explicit `/Script/Engine.AnimSequence` property boundary. It selects exactly one non-template export unless the host supplies an index. No native boundary is found by scanning bytes.

The host supplies optional `CookedAnimationDependency` sources for bone compression settings and the Skeleton. Each owns a copied read-only `Container` handle, entry index, Zen context and read options. A stored local export reference resolves in the main package directly. For an external reference, the supplied package name and nonzero public export hash must match the stored ObjectProperty exactly; ambiguous hashes, wrong classes, templates and missing referenced exports are refused. Dependencies can use independent script/schema/codec contexts in the Core API. There is no implicit directory search, engine execution or arbitrary external loading.

The compression settings require their own decoded explicit `/Script/Engine.AnimBoneCompressionSettings` binding. Its stored `Codecs` ArrayProperty determines registration and lookup order. An arbitrary child with a plausible name is not sufficient. The reader constructs each registered object's actual handle from its child-to-parent FName outer chain, stopping at the verified settings root. The selected exact class must be `/Script/Engine.AnimCompress_PerTrackCompression`. The known built-in BitwiseCompressOnly and RemoveLinearKeys classes allow verification of preceding base lookup behavior, but their decompression is not implemented here. A preceding plugin/custom lookup, external codec registration or unsupported selected codec remains unavailable; its methods are never executed or guessed. Stored and canonical handle spellings remain separate; ASCII case-insensitive comparison follows the verified base FString lookup. Other Unicode case equivalences require additional matching evidence.

Skeleton binding requires its decoded explicit `/Script/Engine.Skeleton` property boundary, exact referenced package/public hash/class and a matching stored Skeleton GUID. The reader validates native reference bone names/parents, double local TRS poses and the name-index map, then bounded stored retarget-source poses through the GUID. Later Skeleton-native data remains a fingerprinted tail. Numeric compressed track indices must exist in this verified reference skeleton before names are assigned. A caller's unrelated bone list cannot supply identities.

## Native coverage and absence

The common native prefix retains UObject GUID presence, cached Skeleton GUID, strip flags, compressed-data presence/raw-size metadata, the compressed track map, indexed curve names, buffer storage, codec handle/path and curve byte hashes. The supported codec's serialized frame/format/view metadata and raw-only flag follow. The views must exactly cover the complete compressed buffer. Per-track translation/rotation global tags are Identity; the stored legacy scale tag is retained and does not override per-key scale headers. Actual per-track decoding/sampling reuses [ANIMATION_COMPRESSION.md](ANIMATION_COMPRESSION.md).

Inline buffers and Zen bulk-map windows are supported, including embedded/external, optional, mapped and duplicate-optional forms. The selected external chunk is read in full with required IoStore BLAKE3-160 integrity before its bounded window is used. Package/dependency reads and used external bytes share the configured aggregate read budget. Missing/unused payloads retain their unavailable state and known frame metadata; declarations are not substituted for decoded channels. Real evidence currently covers inline animation buffers; external animation arrangements additionally have original fixture coverage.

Compressed curves retain their actual indexed names, codec path, byte length/hash and explicit `opaque` coverage. Empty names/bytes are reported as empty. Their values are **not decoded**. A verified empty bone-codec handle with no tracks/buffer consumes no invented codec metadata; curve-only data retains an unknown bone-frame domain. Missing compression settings or unknown lookup behavior leave the codec-specific remainder opaque. Every result retains the main native end offset, parsed-byte count and later tail offset/length/hash.

`Interpolation` is read when explicitly stored as a supported Byte/EnumProperty. If omitted, `CookedAnimationOptions::interpolation` must supply the producer fact for sampling. Omission does not imply Linear, and an explicit value conflicting with a stored value is refused. Native FString decoding honors an explicit option, or the explicit schema-context narrow encoding; otherwise only ASCII narrow strings are accepted. UTF-16 strings validate their own framing and surrogates.

## Sampling and differences

`sample(frame)` accepts a finite fractional frame in the stored compressed domain. It returns numeric tracks and, only with verified Skeleton binding, exact named bone-local tracks. A missing stored track remains absent: no reference-pose fallback, virtual-bone synthesis, additive base, retargeting or component/world-space pose is generated. An omitted interpolation setting makes the sample unavailable. Full Skeleton bone/retarget arrays are returned by `to_json`, rather than duplicated into every sample.

`compare_cooked_animation_frames` pairs exact verified bone names at independently selected fractional frames. It reports position distance, sign-invariant normalized quaternion orientation delta, scale delta, tolerances and known added/removed stored tracks. A missing/unreadable peer or unknown binding yields incomplete coverage and unavailable pairs, never false removals. This comparison covers **selected sampled bone-local channels**, not every stored key, native metadata, curve or complete asset. Complete package/body/property review remains available through Zen inspection/diffs; stored compressed keys can be requested separately.

## CLI

```text
cyuediff zen-animation BUILD.utoc ANIMATION_ID --cooked-profile ue5.3 --animation-profile ue5.3-windows --script-objects global.utoc --schema context.json --bone-settings-entry SETTINGS_ID --skeleton-entry SKELETON_ID --interpolation linear
cyuediff zen-animation-frame BUILD.utoc ANIMATION_ID [same context/dependency flags] --frame 12.5
cyuediff zen-animation-frame-diff BEFORE.utoc ANIMATION_ID AFTER.utoc ANIMATION_ID [independent contexts] --before-frame 12.5 --after-frame 8.5
```

Bracketed text abbreviates complete flags, not literal syntax. `--include-keys 1` includes decoded stored keys in `zen-animation`; metadata is the default. `--export-index` selects an object. `--bone-settings-container` and `--skeleton-container` choose dependency containers; otherwise the respective side's main container is used. Each selected container requires its entry ID. Entry IDs/profile/interpolation inherit before settings for a diff, while dependency containers default to their own side's main input; an external after container must be selected explicitly.

Diff accepts `--after-schema`, `--after-script-objects`, `--after-cooked-profile`, `--after-animation-profile`, `--after-export-index`, `--after-interpolation`, `--after-bone-settings-entry`, `--after-bone-settings-container`, `--after-skeleton-entry`, `--after-skeleton-container` and independent frame numbers. Position/rotation/scale tolerances use the existing CLI names. Each side's dependencies use that side's selected schema/script context. An explicitly supplied `--codec` supplies a host container decompressor when needed; no engine codec is loaded automatically.

Successful inspection returns 0 even when some coverage is explicitly unavailable. Frame sampling returns 2 when unavailable; a known numeric sample without names remains useful. Frame diff returns 0 for identical selected named values, 1 for known changes and 2 for incomplete/error coverage. All opened dependency container partitions, global tables, contexts and mappings are protected output endpoints.

## SDK, validation and remaining integration

The installed `examples/cooked_animation_consumer` links only `CyUEDiff::Core`. It opens complete containers, loads explicit contexts/dependencies and samples all integer/half frames with an explicit Linear producer setting. The public `validate_cooked_animation.py` checks independently exported compressed-codec and Skeleton API values, complete compressed-buffer IoHash, names/indices, reference hierarchy/transforms and GUID agreement, with protected original hashes. JSON serialization is a separate caller allocation; decoded output, keys, source reads and progress/cancellation remain bounded. Class/registration lookups use an indexed export-path table.

Two real cooked animations supply 68 tracks at 377 and 111 sample positions: 331,840 named pose components match direct Unreal compressed-codec API values within 2e-6, largest measured delta 9.4532e-7. The separately decoded Skeleton's names/hierarchy and 680 reference-pose components match the actual Skeleton API exactly; it is checked for each animation. Source/companion/container/global/context/mapping hashes remain unchanged. Original fixtures additionally exercise bulk arrangements, unknown readers, codec registration, invalid dependencies, every native animation/Skeleton truncation, implicit/empty tracks, curve-only coverage, UTF-16/narrow encodings, budgets and cancellation.

A dedicated worker-prepared EN/FR desktop animation path, compressed curve values, additional codecs/engine profiles, runtime retarget/additive/root-motion semantics and further real external-buffer evidence remain open. This reader does not imply overall product completion, a new distributable release or publication.
