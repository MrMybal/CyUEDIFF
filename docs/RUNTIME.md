# Runtime controls and caching

`ReadOptions::control` and `BulkDecodeOptions::control` accept an `OperationControl`. Supply thread-safe callbacks for cancellation and progress; callbacks run on the worker and must not throw. Cancellation throws `Error` with code `cancelled`, propagating through property/native fallback handlers. `sha256_file` and general package comparison accept the same control. Direct Git child processes are terminated and reaped when cancelled.

Reads use chunks no larger than 1 MiB, hashing checks between chunks, compressed buffers check between codec blocks, raw image conversion checks every 65,536 pixels, and the MeshDescription reader checks memory reads. A third-party codec or PNG/JPEG call already in progress returns before its next checkpoint; there is no unsafe forced thread termination. Phase progress is local to the current file/activity and can restart when another file or phase begins. It is not an overall ETA.

`DocumentSession` cancels active work when a newer request arrives. **Cancel loading** sets the active token, drops pending/stale results and preserves the previous document. Closing the session cancels and joins the worker. The UI displays translated phase progress without calling decoders from its draw loop.

`PackageCache` is a reusable, thread-safe Core-only LRU returning immutable shared packages. Every lookup hashes the package and the known `.uexp`, `.ubulk`, `.uptnl`, `.m.ubulk`, `.o.ubulk` and `.upayload` companions. The cache does not trust timestamps or sizes as proof of equality. A new entry is checked again after parsing; source changes during that read are rejected. Reader flags, limits and the immutable decoder registry select distinct cache profiles. Worker callbacks are never retained in an entry.

The default cache retains up to eight packages and 128 MiB of aggregate source bytes. This source budget is not an exact decoded-heap measurement; the reader's independent table/property limits still apply. Larger sources bypass retention. `clear()` releases retained handles; other users can keep an immutable package alive. Nothing is written to disk. Desktop sessions use this cache for local loose packages. Git materialization remains owned by each document and is not shared through the loose-file cache.

The desktop accepts `--project`/`--engine-root` for the before side and optional `--after-project`/`--after-engine-root` overrides. Empty override fields inherit the before selection. Identical long package names can therefore resolve to different content roots and engine contexts. Git mode uses the respective historical project descriptor on each side. These contexts select mounts and installed engine metadata; they do not force an incompatible file serializer version.
